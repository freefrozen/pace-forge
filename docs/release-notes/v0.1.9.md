这一版没有改生成逻辑，只是把「开关到底生效没生效」这件事变得看得见：命令行一条 `config` 命令，Web 启动时打一行非默认项，仓库根补上变更记录。

## 想知道自己设的环境变量有没有生效

`PACE_*` 开关十来个，散在 README 和代码里，排障时最常见的一句是「我明明 export 了怎么没变化」。现在直接问程序：

```
$ pace-forge config

PACE_* 开关（默认值 → 当前值 → 影响）

PACE_STRICT_POLICY = 0
    默认 0：1 = 策略拉取失败直接报错，不走「policy=0」兜底
PACE_STEP_M = 4.5  ← 非默认
    默认 5.0：CLI 的几何采样间距（米），只管形状不管上报节奏
```

表里只列真正存在的开关，默认值和影响写在同一行下面；口令只显示「已设置（不显示值）」，不会把原文打到终端或 CI 日志里。

`web` 启动时也先打一行非默认项，启动日志里就能确认环境对不对：

```
[config] 非默认：PACE_STEP_M=4.5 PACE_FORGE_TOKEN=（已设置）
```

判定「非默认」时踩过一个小坑：原先拿描述性默认值（比如 `28800（东八区）`）去跟原始环境变量串比较，自己手动设成默认值也会被标成非默认。现在每个开关单独存一份可比较的默认值；口令、目录、自动推导这类没有字符串默认的，设了就算非默认。

## 升级前不用再翻八份 release notes

仓库根新增 `CHANGELOG.md`，从 v0.1.1 到本版按版本倒序列出要点，每条带类型标签：

- `[行为变化]` 升级后行为会变，旧用法可能失效
- `[仅修复]` 修正错误，行为不变
- `[仅文档]` 只动说明、注释、元信息

README 的下载章节也加了指向它的链接，选版本前先扫一眼标了 `[行为变化]` 的条目。

## 退出登录不再假装成功

顶部「退出」和列表里每行的「退出」以前不管服务端回什么，界面上都写「已退出」。网络断了或者接口失败时，本地登录态是清了，服务端会话还活着——这时候重登会撞 10121，锁一小时。

现在两处都会看 `remoteLogout`：确认了才说成功，没确认就明说「本地已退出，服务端未确认（半小时内别重登）」。

## 本版其余

`Cargo.toml` 里的 `rust-version = "1.88"` 是上一版补的，这里再说明一次：1.80 报 `edition2024`，1.85 报 `icu_*` 系列需要 1.88，低于 1.88 的 toolchain 直接拒绝编译。
