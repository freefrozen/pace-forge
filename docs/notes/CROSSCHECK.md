# 跨记录自检（crosscheck）

单条记录的自检管的是「这条报文自己圆不圆」；服务端判异常时还会横向看多条：
连续多少天、起跑时刻是不是总在同一分钟、里程和配速的离散度、两次轨迹是不是
同一条线。`pace-forge crosscheck` 把这四项算出来，只给数，不下结论。

## 先导出，再自检

列表接口不带轨迹，要比重合度得先把详情拉下来。两条命令一步到位：

```bash
pace-forge export-records 20 records.json   # 最近 20 条，逐条拉详情取轨迹
pace-forge crosscheck records.json
```

`export-records` 会打印每条的 rrid 与轨迹点数；某条详情拉不到就留空轨迹，
脚本不整体失败。导出文件里 `points` 缺省的记录仍参与连续天数、时刻、离散度。

## 用法

```bash
pace-forge crosscheck records.json
```

文件可以是 JSON 数组，也可以是 `{"records":[...]}`。字段按常见别名挑：

| 需要的量 | 接受的字段名 |
|---|---|
| 起跑时间 | `startTime` / `start_time` / `startMs` / `beginTime`（小于 1e11 按秒，自动乘 1000） |
| 里程（米） | `totalDis` / `distance` / `totalDistance` / `dis` |
| 时长（秒） | `totalTime` / `duration` / `useTime` |
| 轨迹（可选） | `points` / `track`（`[lat,lon]` 或 `{lat,lon}` 都行）、或 `allLocJson` 的 JSON 字符串 |

没有轨迹的记录仍参与连续天数、时刻、离散度，但不参与重合度。

## 输出

```
[记录] 3 条，2026-11-07 ~ 2026-11-09（跨 3 天）
[连续] 最长 3 天，当前一段 3 天
[起跑时刻] 最集中 05:00，占 100%
[里程] 均值 2000m，离散 4.1%
[配速] 均值 5'47"/km，离散 0.9%
[重合] 第 1 条 vs 第 2 条 最高 50%（1 对，30m 缓冲）
```

- 时间全部按本地时区（`PACE_TZ_OFFSET_SEC`，默认东八区）
- 同一天多条记录只算一天，连续天数按去重后的日期算
- 离散度是变异系数（标准差 / 均值），不是绝对差
- 重合度：取两个方向的「点在对方 30 米缓冲内的比例」里较小的那个，避免
  一条短轨迹整段落在长轨迹里被判成 100%

## 边界

- 只做统计，不给阈值。多少算「太集中」「太重合」取决于各校审核规则，
  也取决于自己的实测定论，程序不替人拍板。
- 轨迹坐标系要与比较对象一致（BD-09 和 GCJ-02 混着比，会凭空差出几百米）。
- 30 米缓冲是「同一条路线」的判据，不是「合规」的判据；慢跑时相邻点间距
  十几米，正常同一条路线的逐点偏差一般在 10~20 米内。
